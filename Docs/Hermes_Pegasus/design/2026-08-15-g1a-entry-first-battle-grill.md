# G1-A · 基础入口到可重开首战

> 这是 Run MVP 的第一块窄切片，不是完整主菜单、完整地图、完整存档或完整 roguelike 外层循环。
> 本文记录本轮 Grill 已确认的玩家可见规则与边界；它本身不是代码实施授权。

## 1. 可观察目标

玩家启动后可以走完：

```text
主菜单 → 开始游戏 → 角色选择 → 临时单节点地图 → 战斗
                                      ↑                ↓
                              胜利后回地图      失败页 → 重开本关
```

该链路证明一个 Run 拥有跨页面/场景生命周期，并能把 Battle 的结果接回 Run 流程。

## 2. 已确认的玩家规则

### 2.1 主菜单

- 主菜单的信息架构参考《杀戮尖塔》。
- `开始游戏` 可用。
- `设置` 可用，但本片只包含页面与返回；不冻结音频、显示或输入设置项，也不要求设置持久化。
- `图鉴`、`统计` 可点击，分别进入带返回控件的“开发中”占位页。
- `继续游戏` 本片不需要较真；不因未实现存档阻塞本切片，后续必须能以小改动加入。

### 2.2 角色选择

- 进入新 Run 前先进入角色选择页。
- 当前配置中的两名 Hero 都可选：战士（1001）与机枪兵（1002）。
- 本片每次只选择一名角色开局。
- 角色选择布局为未来 1～4 人组队预留槽位，但不实现多人队伍规则、队伍创建或联网。
- 战士（1001）本轮作为正式“战士”显示，允许后续为其制作选择头像。

### 2.3 最小 Run 与临时地图

- 角色确认创建一个新的 Run。
- 新 Run 先进入临时地图；本片地图只有一个可进入的战斗节点。
- 点击该节点进入 Battle。
- 不实现真实地图生成、路线分叉、奖励节点、商店、事件、篝火或 Boss。

### 2.4 战斗结果与重开

- **胜利**：Battle 结果写回 Run，回到临时地图，节点显示为已完成。
  - 本片没有奖励、下一节点、最终结算页或地图退出按钮。
- **失败**：进入失败页，不作最终 Run 结算。
  - 提供“重开本关”。
  - 重开恢复到进入本战前的 Run 快照。
  - 重新开战时使用新的本战随机输入；不是同种子重放。
- 这为玩家保留 SL（重开本关）体验，但不等于实现存档、继续游戏或完整死亡规则。

## 3. 状态与所有权边界

以下是本切片必须保持的架构口径：

- 主菜单、角色选择、地图、失败页是流程/UI 层：它们只显示 Run 流程状态并提交用户命令，不能保存第二份 Hero、牌组、生命、节点或随机状态。
- Run 是跨场景权威状态的唯一所有者；它至少需要持有选中 Hero、Run 身份、当前节点、进入战斗前快照和本战输入所需的随机事实。
- Battle 仅从 Run 提供的输入快照创建 Session；Battle 的胜利结果只能通过一个原子边界写回 Run。
- 失败的“重开本关”从 Run 保存的进战前快照恢复，不接受 Battle 失败后的临时生命/牌组状态；新战斗随机输入由 Run/Flow 层重新派生。
- UI 不能直接构造或修改 BattleSession、BattleResult 或 RunState；具体服务/Scope 名称仍待技术审计后决定。

## 4. 美术与界面边界

- 当前没有冻结入口屏幕构图；先做 `ENTRY-CONCEPT-001`，再决定标题、菜单列与背景留白。
- 入口整体概念由用户逐张生成、审阅和保存：先总概念，后背景、选择头像、零部件。
- 图像生成范围：主菜单背景、战士头像、机枪兵头像；正式标题优先复用已有候选。
- SVG/Unity UI 范围：按钮底板、角色卡槽、单节点、失败页、占位页、设置页和轻量转场。
- 图片不生成文字、数字、菜单标签、UI 框或图标；这些由 Unity TMP/i18n 绘制。

详见 `Docs/Hermes_Pegasus/art/entry-ui-asset-checklist.md`。

## 5. 明确排除项

- 存档、跨进程恢复、继续游戏。
- 真实设置功能与设置持久化。
- 真实地图算法和多节点流程。
- 奖励、卡牌获得/升级、遗物、药水、金币、商店、事件、篝火、Act、Boss。
- 失败后的永久 Run 结束规则、主动放弃 Run、地图返回主菜单。
- 多角色队伍运行时、联网、匹配、同步。
- 正式入口美术定稿、批量图像生成和正式资源替换。

## 6. 计划前的技术核对问题

计划阶段必须在现有工程中核实，而不是凭本页猜定：

1. Bootstrap、场景切换、VContainer scope 与现有 BattleSession 的真实生命周期入口。
2. 现有不可变 BattleResult 的发布时机、内容，以及它能否作为 Run 写回的唯一读取边界。
3. Hero/Deck 配置、当前生命和战斗种子的最小输入如何不复制事实地进入 Battle。
4. 最小单节点地图、失败页和导航页面怎样接入，而不让 UI 反向持有 Run 状态。
5. 能以何种 Unity 原生测试与 PlayMode 路径证明：新 Run、胜利回图、失败重开新随机、旧 Battle Scope 清理。

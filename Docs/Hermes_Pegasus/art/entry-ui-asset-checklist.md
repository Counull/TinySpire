# TinySpire · G1-A 基础入口美术清单

> 用于“主菜单 → 角色选择 → 临时单节点地图 → 首战 → 胜利/失败返回”的美术迭代。
> 本页是资产生产队列，不替代玩法边界、实现计划或正式采用记录。每个候选都须经用户确认后才可提升为正式资源。

## 0. 已确认的范围边界

- 主菜单、角色选择、临时单节点地图与失败页需要可读的视觉入口。
- 首片选择两名现有 Hero：战士（1001）与机枪兵（1002）；本次单角色开局，界面为未来组队留位置。
- 图鉴/统计只进入“开发中”占位页；设置本片只有页面与返回，不锁真实设置项。
- 不在本片生成带文字、数字、按钮标签、统计数据或设置选项的图片；这些都由 Unity TMP/i18n 渲染。

## 1.1 先做入口概念，不先锁构图

当前还没有经过确认的“入口屏幕概念”，因此标题位置、菜单列位置、角色选择的舞台关系都**不是**可直接写进背景 prompt 的事实。

- `ENTRY-CONCEPT-001`：先产出 2～3 个 16:9 入口屏幕构图概念，比较标题、菜单、角色选择与背景留白的关系；概念图中的文字只可作为排版占位，不能当作正式 UI 资产。
- 概念选定后，才冻结主菜单背景所需的安静区域、标题位置和菜单列位置。
- 代码可以同步搭建可替换的页面壳、导航和 SVG 几何组件，但不要为未定构图生产正式背景或把坐标写死为视觉规范。
- **审阅节奏**：用户会在单独的美术/Grill 回合中躺着逐张生成、审阅和保存；先定整体入口概念，再按需要逐项生成背景、角色头像和零部件。不要预先批量生产或一次性把整套资产定稿。

### 图像生成共同约束

- 使用 `ANCHOR-001` 作为唯一参考图；角色生成还必须优先使用各自最终三视图/角色参考，而不是从职业名称脑补。
- 生成候选保存为 `ref_vNN`；不覆盖标题、角色立绘或 Unity 正式资源。
- 图像模型不承担文字、UI 框、按钮、数字或图标。
- 每批只出同一类别的少量候选，用户选中后才做抠图、尺寸/alpha 核验和正式化。

## 4. 目前不需要生产

- 图鉴内容卡、统计图表、真实设置图标或设置滑块皮肤。
- 奖励、遗物、商店、事件、篝火、完整地图路线相关素材。
- “继续游戏”按钮的正式视觉状态：G2 的存档/恢复规则确定后再加。
- 战斗角色三视图替代品、动态逐帧角色动画、带文字的标题重绘。

## 5. 推荐的同步生产顺序

1. 先完成 `ENTRY-CONCEPT-001`，选择入口屏幕的构图方向；概念不是正式资源。
2. 同步用 SVG/Unity UI 搭出可替换的页面壳、导航、选择卡、单节点与失败页，不把未定构图坐标固化。
3. 确定主菜单标题位置与按钮列位置后，为 `ENTRY-BG-001` 写一个窄 prompt 并出少量背景草图。
4. 并行整理战士与机枪兵的角色 brief/参考；身份锚点足够后再生成两张选择头像。
5. 将确认的候选放进真实 UI 进行截图验收：文字可读、肖像不抢按钮、节点三态无需文字也可区分。
6. 只有用户选择候选后，才将资源提升到正式资产路径并登记采用关系。

## 6. 验收清单

- 背景不含烤死的文字、UI、Logo、人物或错误平台符号。
- 头像在 128–192 px 仍可区分职业与姿态；不以“更帅”替代身份准确。
- SVG 几何控件可由 Unity 拉伸/换文本而不变形；标签不嵌入位图。
- 所有候选保留原图；透明 PNG 必须有真 alpha、无键色边缘和错误透明化。
- 正式化前，用户明确选中候选；候选不等于正式资产。

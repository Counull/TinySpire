# TinySpire · Run MVP 路线图

> **当前路线入口。** 后续任务中提到“Roadmap / 跑路线图”，默认指向本文；旧 `ROADMAP.md` 只用于追溯已冻结的 BattleScene MVP（M0～M10）。当前动态状态仍查 `SESSION_LOG.md`。

> BattleScene MVP 的冻结路线见 [ROADMAP.md](ROADMAP.md)。当前动态状态只查 [SESSION_LOG.md](SESSION_LOG.md)。G1-A 已完成独立 Grill、计划、实现和验证；这不等于整个 G1 或任何 G2+ 范围获得授权。

## 1. 当前起点与终点

起点是 2026-08-14 的 BattleScene MVP 检查点：Git commit `e07e39a`，tag `milestone-battlescene-mvp-2026-08-14`，最新完整 Unity EditMode 记录为 **807/807 passed**。单场战斗、基础卡牌内容、权威命令队列、结算与功能性反馈已经形成可复用底座。

Run MVP 的终点不是“把所有 STS 内容做完”，而是至少用一个角色、一个 Act 和一个 Boss 贯通：

```text
主菜单 → 新 Run → 地图 → 多个节点 → Boss → Run 结算 → 主菜单
```

贯通过程中，牌组、生命、金币、地图位置与确定性随机事实必须跨场景连续；任何 UI 都只能派生和提交命令，不能成为第二份 Run 状态。

当前 BattleScene UI、视觉反馈与动画是功能性基线，仍属 provisional。除非某个 Run 切片因可读性或可操作性确实被阻塞，否则表现重做不抢占游戏本体的阶段顺序；它们进入第 6 节的独立债务轨道。

## 2. Roadmap、切片与 Grill 的职责

本文件只回答三个问题：阶段为什么存在、阶段之间如何依赖、阶段完成后能观察到什么。它不决定具体类名、Scene/Prefab 结构、表字段、按钮文案或一次提交包含多少文件。

每个可执行切片必须经历以下门禁：

1. **提名**：从当前阶段挑一个最小可观察结果，只登记范围与依赖，状态为 `needs-grill`。
2. **局部 Grill**：只追问这个切片的玩法事实、生命周期、失败语义、数据所有权、UI 边界、验收和明确排除项；不顺带 Grill 整个 G1 或整个 Run。
3. **窄计划**：把已确认答案写入 `plans/`，列出影响路径、回滚方式和串行停止点；计划状态仍不等于实施授权。
4. **明确授权**：用户明确批准该计划后，才能进入 TDD / 实现 / 表格 / Scene / Prefab 等写入。
5. **验收与沉淀**：完成代码、配置、Unity 原生验证和 Wiki 闭环后，才把切片标记为 `verified`。

如果一个切片在设计或实现中拆出具有独立玩法选择、生命周期边界、高影响文件或失败语义的子切片，该子切片回到 `needs-grill`，不能继承父切片的授权。纯机械接线、同一已冻结契约下的测试补齐和生成物同步不重复 Grill。

## 4. G1 当前状态：G1-A verified，阶段剩余范围未授权

G1-A「基础入口 → 角色选择 → 临时单节点地图 → 首战 → 胜利回图 / 失败可 SL 重开」已于 2026-08-16 完成真实验证：

- Bootstrap 默认进入单一 `RunEntryScene`；主菜单、设置/占位页、双 Hero 单选、临时地图和失败页都在该 Scene 内切换。
- `RunStateStore` 唯一拥有跨场景事实与 snapshot；`RunFlowService` 只编排。Battle 经现有 setup seam 消费 Hero、当前生命、牌组模板与 seed；Battle 只经稳定 `BattleResult` bridge 写回。
- 1001 胜利后以 17/30 回图并完成节点；1002 失败后恢复 70/70 snapshot，重开签发新 attempt/new seed 且创建干净 BattleSession。
- `Sync and Build All`、Packed Play Mode 真实 bundle 链和完整 EditMode 873/873 已通过。权威动态记录与风险见 [SESSION_LOG.md](SESSION_LOG.md)，详细证据见 [06_testing/2026-08-16-g1a-entry-first-battle-run-lifecycle.md](06_testing/2026-08-16-g1a-entry-first-battle-run-lifecycle.md)。

G1-A 明确没有实现存档、继续游戏、主动退出 Run、永久死亡、奖励、多节点/分叉、真实地图生成或 Run 结算，因此不能把本切片的 `verified` 扩张为整个 G1 已完成。任何上述后续结果都要重新提名、局部 Grill、形成窄计划并获得授权。

## 5. G2～G8 待 Grill 候选骨架

以下内容从旧 Roadmap 迁移，用于未来各阶段 Grill 时防止遗漏，不是已确认规格。字段、公式、数量、页面、Scene、服务名、实现顺序和验收细节都必须在对应切片中重新确认。

### G2 · RunState、存档与确定性

- 候选问题：非战斗期间由什么聚合拥有角色、生命、牌组、金币、遗物、药水、地图位置和随机状态。
- 候选问题：战斗内外的生命写权限如何转移，战斗结果怎样一次写回。
- 候选问题：存档是否需要稳定 ID、schema version 和迁移入口，以及明确排除哪些 Unity / 派生对象。
- 候选结果：恢复后不复制奖励、不重复扣费，并保持后续随机序列可复现。

### G3 · 地图生成与节点流程

- 候选问题：地图是否采用有向无环图、节点/边由谁拥有、可选节点怎样派生。
- 候选问题：地图选择和节点返回使用何种命令/结果边界。
- 候选结果：同一冻结输入可复现合法且可达的路线；Boss 和节点分布规则留到 G3 切片 Grill。

### G4 · 战斗结果、奖励、卡牌获得与升级

- 候选问题：战斗结果生成哪些奖励、候选何时冻结、重开 UI 是否允许重随机。
- 候选问题：选择/跳过奖励修改哪个权威事实，以及下一场战斗如何实例化牌组。
- 候选问题：升级事实放在何处；在该问题被 Grill 前，现有“升级仅 metadata”的运行时边界保持不变。

### G5 · 遗物、药水与触发时机

- 候选问题：遗物/药水是否需要模板与 Run 实例、槽位和持有量由谁拥有。
- 候选问题：触发时机词汇、稳定顺序和跨 Battle / Run 的所有权，以及是否/如何接现有结算队列。
- 候选结果：UI 不成为效果写入口；一次性消费和战斗结束清理可验证。

### G6 · 商店、事件、休息点与宝箱

- 候选策略：每类节点先交付一个完整竖切，再决定内容池扩充。
- 候选问题：库存、价格、事件选项和宝箱奖励何时成为事实，交易/选择怎样提交。
- 候选结果：重进场景不重复领取、不意外刷新候选，也不能绕过已冻结的资源门禁。

### G7 · Act、精英、Boss 与内容生产

- 候选问题：是否以及如何按 Act 组织遭遇、事件、奖励与 Boss 池。
- 候选问题：Boss 阶段由谁拥有，UI 如何派生。
- 候选结果：内容生产门禁能拒绝已确认类型的无效引用、空候选、不可达路线、重复唯一奖励和缺失本地化。

### G8 · 完整产品收尾

- 候选范围：设置、教程、可访问性、音频、VFX、过场、结算统计与 Run 历史。
- 候选结果：收口当前 provisional 的 BattleScene / Run UI、动画与视觉反馈，同时保持表现层不成为权威写入口。
- 候选验收：存档兼容、崩溃恢复、性能、分辨率、平台构建和完整 Run 回归；具体矩阵另行 Grill。

## 6. 表现债务轨道

当前对 UI 与动画“不够满意”是已知产品债，不等于 BattleScene 规则里程碑未完成。后续按以下方式管理：

- 不因审美调优中断 G1～G7 的核心事实与流程竖切。
- 当某个新切片因可读性、输入反馈或流程理解无法验收时，只补该切片所需的最小表现。
- 大范围视觉语言、动效节奏、HUD 重排、Prefab/Scene 重构和可访问性统一进入独立表现切片，分别 Grill、授权和验收。
- G8 负责最终产品级统一，但不禁止更早偿还会阻塞玩法验证的局部表现债。
